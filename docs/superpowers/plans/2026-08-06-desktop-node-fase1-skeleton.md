# Fase 1 — Desktop Node Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up a working, testable Electron + React + TypeScript desktop skeleton at `desktop-node/` — DB schema, migrations, a simplified login, and a placeholder home screen — proving the full main↔preload↔renderer↔SQLite chain works end to end, with zero changes to the existing Laravel app.

**Architecture:** Electron main process hosts all logic directly (no HTTP server). Renderer talks to main exclusively via `contextBridge`-exposed `window.api.*` functions that wrap `ipcMain.handle` calls. SQLite via `better-sqlite3`, schema/migrations via Drizzle ORM. React Router (`HashRouter`) handles in-app navigation.

**Tech Stack:** electron-vite (scaffold), Electron, React 19 + TypeScript, react-router-dom, better-sqlite3, drizzle-orm + drizzle-kit, bcryptjs, Vitest.

## Global Constraints

- New code lives entirely under `desktop-node/` at the repo root. Do not modify `app/`, `routes/`, `resources/`, `nativephp/`, `composer.json`, or any other existing Laravel file — the current app keeps running unchanged (strangler migration, per `docs/superpowers/specs/2026-08-06-electron-node-migration-design.md`).
- No HTTP server anywhere in `desktop-node/`. All renderer↔main communication is IPC via `contextBridge`/`ipcMain.handle`.
- DB: SQLite via `better-sqlite3`, schema/migrations via Drizzle ORM. No other ORM.
- Auth is simplified: single `users` table (username + password hash), no 2FA/passkey/self-registration. Password hashing via `bcryptjs` (pure JS — avoids a second native module alongside `better-sqlite3`).
- Renderer routing via `react-router-dom`'s `HashRouter` (not `BrowserRouter` — app loads from a local file, not a real HTTP origin).
- Tests via Vitest. Business/auth logic must be written as plain functions importable without booting Electron, so they're unit-testable.
- Schema must match the existing Laravel migrations column-for-column (source of truth: `database/migrations/*create_{products,categories,product_units,product_price_tiers,product_price_histories,suppliers,purchases,purchase_items,sales,sale_items,bon_payments,stock_adjustments,store_settings}*.php`), except `users`, which is new/simplified for this app.
- Printing, barcode scanning UI, and all business pages (Kasir, Inventory, etc.) are **out of scope** for this plan — Fase 2+.

## Environment Notes (native module toolchain — read before Task 3 or Task 7)

`better-sqlite3` is a native module and needs a working C++ toolchain to build. On this dev machine:

- The bundled npm's `node-gyp` (9.4.x) does not recognize the installed Visual Studio 2026 Build Tools ("unknown version 'undefined'") — this is a real node-gyp version limitation, not a missing-toolchain problem. Fix already applied: `node-gyp@latest` (13.x, which does support VS 2026) was added as a devDependency in Task 1. If a fresh checkout hits the same "could not find any Visual Studio installation to use" error, the fix is `npm install -D node-gyp@latest` then rebuild (see below) — do not attempt to install a different Visual Studio version.
- `better-sqlite3`'s compiled `.node` binary is ABI-specific: **plain Node** (used by Vitest — Tasks 3, 4, 5) and **Electron's bundled Node** (used by `npm run dev` — Task 7) need *different* builds of the same file, and installing one overwrites the other. As of the end of Task 1, the module is built for **plain Node** (Vitest works). Task 7's manual verification (which runs the real Electron app) must run `npm run rebuild:electron` (added in Task 1 — wraps `electron-builder install-app-deps`) immediately before `npm run dev` to switch to the Electron ABI. Nothing after Task 7 needs the plain-Node ABI again in this plan, so no further switching back is required.
- If a build ever needs to switch back to plain Node (e.g. re-running Vitest after Task 7), run `npm rebuild better-sqlite3` from a Visual Studio Developer Command Prompt (or `cmd /c` with `vcvars64.bat` called first) — plain `npm rebuild` from a regular shell will fail with the VS-detection error above unless `cl.exe` is already on `PATH`.

import { drizzle } from 'drizzle-orm/better-sqlite3'
import { migrate } from 'drizzle-orm/better-sqlite3/migrator'
import * as schema from './schema'

export function createDb(dbPath: string, migrationsFolder: string) {
  const sqlite = new Database(dbPath)
  sqlite.pragma('foreign_keys = ON')
  const db = drizzle(sqlite, { schema })
  migrate(db, { migrationsFolder })
  return db
}

- [ ] **Step 3: Write the implementation**

Create `desktop-node/src/main/auth.ts`:

```typescript
import bcrypt from 'bcryptjs'
import { eq } from 'drizzle-orm'
import type { BetterSQLite3Database } from 'drizzle-orm/better-sqlite3'
import * as schema from './db/schema'
import { users } from './db/schema'

export interface AuthUser {
  id: number
  username: string
  name: string
}

export function verifyLogin(
  db: BetterSQLite3Database<typeof schema>,
  username: string,
  password: string,
): AuthUser {
  const row = db.select().from(users).where(eq(users.username, username)).get()
  if (!row) {
    throw new Error('Username atau password salah')
  }

  const valid = bcrypt.compareSync(password, row.passwordHash)
  if (!valid) {
    throw new Error('Username atau password salah')
  }

  return { id: row.id, username: row.username, name: row.name }
}
```

## Task 6: IPC auth handlers + preload bridge

**Files:**
- Create: `desktop-node/src/main/ipc/auth.ts`
- Modify: `desktop-node/src/preload/index.ts`

**Interfaces:**
- Consumes: `verifyLogin`, `AuthUser` (Task 5), `BetterSQLite3Database` instance (Task 3, wired in Task 7).
- Produces: `registerAuthIpc(db)` — registers `auth:login`, `auth:logout`, `auth:me` IPC channels, consumed by Task 7. `window.api.auth.{login,logout,me}` exposed to the renderer, consumed by Task 7's Login/Home pages.

- [ ] **Step 1: Write the IPC handlers**

Create `desktop-node/src/main/ipc/auth.ts`:

```typescript
import { ipcMain } from 'electron'
import type { BetterSQLite3Database } from 'drizzle-orm/better-sqlite3'
import * as schema from '../db/schema'
import { verifyLogin, type AuthUser } from '../auth'

let currentUser: AuthUser | null = null

export function registerAuthIpc(db: BetterSQLite3Database<typeof schema>) {
  ipcMain.handle('auth:login', (_event, username: string, password: string) => {
    currentUser = verifyLogin(db, username, password)
    return currentUser
  })

  ipcMain.handle('auth:logout', () => {
    currentUser = null
  })

  ipcMain.handle('auth:me', () => {
    return currentUser
  })
}
```

- [ ] **Step 2: Expose it in the preload script**

import { useState, type FormEvent } from 'react'
import { useNavigate } from 'react-router-dom'

export function Login() {
  const [username, setUsername] = useState('')
  const [password, setPassword] = useState('')
  const [error, setError] = useState<string | null>(null)
  const navigate = useNavigate()

  async function handleSubmit(event: FormEvent) {
    event.preventDefault()
    setError(null)
    try {
      await window.api.auth.login(username, password)
      navigate('/')
    } catch (err) {
      setError(err instanceof Error ? err.message : 'Gagal login')
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <h1>Login</h1>
      {error && <p role="alert">{error}</p>}
      <label>
        Username
        <input value={username} onChange={(event) => setUsername(event.target.value)} />
      </label>
      <label>
        Password
        <input
          type="password"
          value={password}
          onChange={(event) => setPassword(event.target.value)}
        />
      </label>
      <button type="submit">Masuk</button>
    </form>
  )
}

}

import { app, BrowserWindow } from 'electron'
import path from 'node:path'

function createWindow(): void {

    },
